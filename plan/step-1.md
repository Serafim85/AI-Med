## 1. Контекст проекта

Разрабатываем **веб-приложение — AI-ассистент врача на приеме**.

**Идея:** во время очного приема приложение записывает диалог врача и пациента, в реальном времени распознает речь, структурирует информацию, предлагает топ-3 предположительных диагноза и план лечения. Врач редактирует и подтверждает итоговый протокол, после чего приложение формирует PDF.

**Пользователи (в MVP только две роли):**
- **Врач** — единственный интерактивный пользователь; управляет сессией, редактирует и подтверждает.
- **Пациент** — участник диалога, с интерфейсом не взаимодействует.

**Что входит в MVP (общий скоуп всех 5 шагов):**
- авторизация врача (логин/пароль),
- создание сессии приема с ручным вводом данных пациента (ФИО, возраст, пол),
- фиксация согласия пациента на запись,
- запись аудио и потоковая расшифровка с разделением говорящих,
- ручная правка расшифровки,
- автоматическое структурирование протокола (жалобы, анамнез, осмотр),
- топ-3 диагноза + красные флаги,
- план лечения (медикаменты, дообследование, рекомендации),
- подтверждение протокола врачом → генерация PDF,
- просмотр своих завершенных сессий.

**Чего в MVP НЕТ:**
- интеграций с МИС/ЕГИСЗ/лабораториями/аптеками,
- истории пациента между сессиями,
- ролей администратора и медэксперта,
- электронной подписи,
- мобильного приложения,
- мультиязычности (только русский).

## 2. Зафиксированный tech stack (обязателен для всех шагов)

**Backend:**
- Python 3.11+
- FastAPI (ASGI, uvicorn)
- SQLAlchemy 2.x (async) + Alembic для миграций
- PostgreSQL 16
- Pydantic v2 для DTO/валидации
- `passlib[bcrypt]` для паролей, `python-jose` для JWT
- `pytest` + `httpx` для тестов

**Frontend:**
- React 18 + TypeScript
- Vite (сборка и dev-server)
- TailwindCSS для стилей
- React Router v6
- TanStack Query (react-query) для серверного стейта
- Zustand для лёгкого клиентского стейта
- axios для HTTP

**ASR и LLM:**
- OpenAI API (Whisper для распознавания, gpt-4o-mini для LLM-задач) — ключ берется из `OPENAI_API_KEY`
- Интерфейсы для ASR и LLM должны быть абстракциями, чтобы можно было подменить на локальные модели.

**PDF:** WeasyPrint на backend.

**Инфраструктура:**
- Docker + Docker Compose для локальной разработки (сервисы: `backend`, `frontend`, `db`)
- `.env` файлы для секретов, `.env.example` в репо.

## 4. Конвенции

- **Названия URL:** `/api/v1/...`, kebab-case в путях.
- **Формат ответов:** JSON. Ошибки в формате `{ "detail": "..." }`.
- **Локаль:** UI — русский. Идентификаторы, коды — английские.
- **Идентификаторы сущностей:** UUID v4.
- **Часовые зоны:** все timestamps — UTC в БД, отображение — локальное в UI.
- **Коммиты:** Conventional Commits (`feat:`, `fix:`, `chore:` и т.д.).

## 5. Задача ЭТОГО шага (Шаг 1)

Создать **скелет монорепозитория** и поднять локальное окружение. **Никакой бизнес-логики, никакой авторизации, никаких моделей пациента** — всё это будет в следующих шагах.

### 5.1. Backend (минимум)
- Инициализировать Python-проект через `pyproject.toml` (можно `poetry` или `pip + requirements.txt` — на выбор, но зафиксировать).
- Настроить FastAPI-приложение `app/main.py` с:
  - CORS (разрешить `http://localhost:5173`),
  - префиксом `/api/v1`,
  - единственным роутом `GET /api/v1/health` → `{"status": "ok"}`.
- Конфиг через `pydantic-settings`, читающий `.env` (поля: `DATABASE_URL`, `JWT_SECRET`, `OPENAI_API_KEY`, `CORS_ORIGINS`). В `.env.example` должны быть все переменные.
- Структуру папок `app/api`, `app/core`, `app/db`, `app/models`, `app/schemas`, `app/services` создать с пустыми `__init__.py`.
- Подготовить подключение к Postgres (через SQLAlchemy async), но **таблиц пока не создаём**. Просто убедиться, что коннект не падает при старте (опционально — ping в `startup`).
- Настроить Alembic, но без миграций — только `alembic.ini` и `env.py`, готовые к использованию.
- `Dockerfile` для backend (Python 3.11-slim, uvicorn).

### 5.2. Frontend (минимум)
- Инициализировать проект через Vite (`react-ts` template).
- Подключить TailwindCSS.
- Подключить React Router с одним роутом `/` → страница `HomePage` с надписью **«AI-ассистент врача»** и кнопкой, которая дергает `GET /api/v1/health` и показывает результат.
- Настроить axios-клиент, читающий `VITE_API_BASE_URL` из env.
- Подключить TanStack Query (`QueryClientProvider` в корне).
- `Dockerfile` для frontend (node-alpine, dev-режим через `vite`).

### 5.3. Docker Compose
- Сервисы:
  - `db` — `postgres:16`, volume для данных, порт 5432, переменные из `.env`,
  - `backend` — сборка из `backend/Dockerfile`, зависит от `db`, порт 8000,
  - `frontend` — сборка из `frontend/Dockerfile`, порт 5173.
- Один общий `.env` в корне для compose + по `.env.example` в каждом сервисе.

### 5.4. README
- Короткое описание проекта и скоупа MVP.
- Инструкция запуска: `docker compose up --build`.
- Как проверить: открыть `http://localhost:5173`, нажать кнопку — должно прийти `{"status": "ok"}`.
- Раздел «Структура репозитория».
- Раздел «Требования к окружению» (Docker, Node 20+, Python 3.11+ для локального запуска без докера — опционально).

## 6. Definition of Done (критерии приёмки Шага 1)

1. `docker compose up --build` поднимает три сервиса без ошибок.
2. `curl http://localhost:8000/api/v1/health` возвращает `{"status":"ok"}`.
3. `http://localhost:5173` открывается, видна надпись и кнопка; по клику — на экране отображается ответ health-check'а.
4. В консоли backend нет ошибок подключения к БД.
5. Alembic настроен: `alembic current` выполняется в контейнере backend без ошибок.
6. В репозитории есть `.gitignore` (Python, Node, IDE, .env).
7. README покрывает все шаги запуска с нуля.
8. Ни одного TODO, связанного с доменной логикой, в коде нет — только чистый скелет.

## 7. Явные ограничения этого шага

- **НЕ создавать** таблицы в БД, модели, схемы пациента/сессии/пользователя.
- **НЕ реализовывать** авторизацию, регистрацию, JWT.
- **НЕ интегрировать** OpenAI/Whisper/WeasyPrint — только добавить переменные окружения и заглушки-сервисы в `app/services/` допустимы, но вызывать их не нужно.
- **НЕ делать** продакшн-конфиг (nginx, gunicorn и т.п.) — только dev.
